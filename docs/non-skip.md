# 非 Skip 优化方案

## 当前版本已有的优化

同帧重复到账图标动画合并适用于所有 replayOwner > 0 的受跟踪结算动画，并不只限 Skip。保留每笔到账通知，只减少同一帧重复创建的晃动与缩放动画。

Skip 空协程合并要求季节已处于 Complete；不会强行压缩正常回放中的真实等待。因此不能把 Skip 加速幅度外推到普通模式。

## 建议顺序

| 方案 | 预期作用 | 表现影响 | 状态 |
| --- | --- | --- | --- |
| 同帧重复图标动画合并 | 降低动画创建、销毁峰值 | 合并同帧重复反馈 | 0.2.0 已实现；非 Skip 尚未专门实测 |
| 同图标跨帧动画复用 | 避免每次重新 Kill/创建 | 连续反馈更平滑，需验证复位和 owner 清理 | 待开发 |
| 飞行图标/飘字对象池及可见数量上限 | 减少对象创建和渲染峰值 | 减少重复视觉个体；每笔到账回调必须保留 | 待开发 |
| 脏数据驱动的效果快照更新 | 减少逐事件全局 ReadCore/BuildFrame | 目标是保持中间数值精确 | 待研究，收益可能较大，正确性要求高 |
| 可选精简回放模式 | 降低快照与动画工作量 | 改变中间详情更新粒度及展示节奏 | 可选路线，默认不启用 |

## 为什么不直接套用季节快照

现有一次离线样本中，非季节快照计算约 29.76 秒，季节快照约 2.21 秒，且最终状态比较一致。但该测试没有逐帧渲染；它不证明正常播放中的每个中间显示状态一致，也不是帧率提升倍数。

Skip 原本就开启季节快照。对非 Skip 强制开启会改变快照粒度，因此不放进当前默认补丁。

## 精确快照优化的验证要求

需要梳理每类事件对建筑、相邻关系、政策和全局效果的依赖，准确标记脏对象。不能只按建筑 ID 缓存，因为相邻建筑或政策变化也可能影响结果。

以旧实现为基线，对同一批事件逐个比较：
- 资源、国力、建筑状态与最终存档快照；
- 每个回放点的属性和效果详情；
- 随机数消耗顺序；
- 跨季、跨年、合成、拆除和政策联动边界。

## 下一次非 Skip 测量

使用同一结算前存档的隔离副本，固定游戏速度和窗口焦点，比较原版与 0.2.0。记录：
- 计算阶段墙钟时间与 CPU 累计时间；
- Replay、ReadCore、BuildFrame 的次数和耗时；
- 帧间隔分布、最长帧、动画实例峰值；
- 同帧动画合并数、季节收尾超时次数。

正常动画播放造成的等待与真正低帧率应分别报告。不能为了缩短等待删除经济到账回调、跳过真实结算，或只缩短 watchdog 超时。
